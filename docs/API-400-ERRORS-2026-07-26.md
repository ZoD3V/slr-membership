## Catatan

- No. 1–7 semuanya endpoint yang membaca tabel `payments`. Endpoint lain sehat: `/billing/status`, `/memberships/me`, `/entries/`, `/subscriptions/` semua 200 dengan token yang sama.
- No. 2 dan 3 **sebelumnya normal** — masih `200` pukul 10:43 UTC, sudah `400` pukul 12:24 UTC. Mohon cek deploy di rentang itu.
- Bukan kesalahan payload: param yang sengaja salah (`per_page=101`, `status=FOO`, `userId=abc`) dijawab `VALIDATION_ERROR` lengkap dengan nama field. Param yang benar justru dijawab `BAD_REQUEST` generik.
- Bukan masalah auth: tanpa token → `401`; token yang sama di endpoint lain → `200`.
- Dugaan: schema `billing/invoices` baru bertambah 6 kolom metadata (`currency`, `hosted_invoice_url`, `payment_method_brand`, `payment_method_last4`, `state_snapshot`, `sub_tier_snapshot`), tapi kolomnya belum ada di database → query melempar exception.
- No. 8 terpisah: backend menyetel `allow_promotion_codes` dan `discounts` sekaligus, ditolak Stripe. Akibatnya `couponId` tidak bisa dipakai sama sekali — ini memblokir Spin Wheel.
- `requestId` di body identik dengan header `x-request-id`, bisa langsung di-grep di log.
